Process Reward Signals for Guided Retrieval
Rajat Patel  ·  Reinforce Labs Assessment  ·  April 27, 2026

The Problem

Final-report quality is a weak control signal for deep research — delayed, hard to credit-assign, and easy to game with confident synthesis.
Pathology 1
They search broadly but don't know which steps were useful. No credit assignment.
Pathology 2
They collapse conflicting evidence into fake consensus. Confident prose covers disagreement.
Pathology 3
They stop when they can write an answer, not when evidence is genuinely exhausted.
  • No per-step evaluation → no sparse reward signal to guide planning
  • No conflict representation → hallucinated consensus in the report
  • No coverage tracking → unknown sub-questions silently skipped
  • No evidence state → output quality opaque and unauditable

Thesis — Two Angles

Angle 1 — the steering mechanism
Process reward
Final-report scoring is too delayed and too weak. Score each step: did this improve the evidence state?
Angle 2 — the objective
Epistemic honesty
Progress = finding real evidence, surfacing contradictions, reducing uncertainty — not fluent synthesis.
A useful research step is one that improves the evidence state honestly. The report is a rendered view over that state — not the primary artifact.
  • Evidence state is the belief state — report is rendered from it
  • PRM literature: intermediate signals beat outcome-only evaluation
  • Epistemic honesty without process reward = just a reporting principle
  • Process reward without epistemic honesty = optimizes for smart-looking behavior

Design Principles

1
Explicit evidence state.Reason over structured external state, not prompt history. EvidenceStore is the belief state.
2
Claims as unit of accountability.Every report statement maps to a scoped, independently testable claim in the store.
3
Search as a policy.Next query chosen from current evidence state: thin coverage, unresolved conflict, unchallenged claims.
4
Falsification before confidence.Decomposer generates adversarial sub-questions targeting failure cases and criticisms, not just support.
5
Surface conflict, don't collapse it.Credible source disagreement is preserved and surfaced. Fake consensus is a failure mode.
6
Confidence must be evidential.Confidence set by source count, diversity, empirical type, challenge status — not writing style.
7
Stop on diminishing information gain.Stop when additional steps no longer improve evidence state AND coverage is met. Not when an answer exists.
8
Evaluate honesty, not plausibility.No ground truth. Check whether the system is honest relative to the evidence it actually collected.

The EvidenceStore — Belief State

Entities tracked
  • SubQuestions — supporting + adversarial, coverage tracked per-kind
  • Observations — raw retrieval results, domain-scored (0.0–1.0)
  • Claims — typed (empirical / speculative), scoped, provenance-linked
  • Adjacent claims — below domain threshold, quarantined from groups
  • ClaimGroups — semantic clusters with group-level confidence + challenge status
  • StepRecords — 14+ diagnostic fields per step
  • LLMCallRecords — full prompt/response trace per component

The PRM Proxy — Step Classifier

Step outcome labels (evaluator.py)
NEW_EVIDENCE CONFLICT_FOUND REDUNDANT DEAD_END
  • Deterministic in MVP: checks new claim IDs, new domains, dispute flips
  • Production: trained PRM scoring (state, action, result) end-to-end
  • Reward values: NEW_EVIDENCE=1.0, CONFLICT_FOUND=0.7, REDUNDANT=0.3, DEAD_END=0.0
Analogy
"This is what o1 does — spending more compute on hard sub-problems — but at the retrieval level instead of the reasoning level."
  • Search-R1 connection: RL for interleaved search and reasoning
  • Test-time compute scaling: budget allocation via step quality signal
  • Outcome-only eval (rate the report) is insufficient for guiding iterative research

Research Frontier — Where This Sits

Papers this design connects to
  • Search-R1 (2025) — search as part of the reasoning trajectory; our planner approximates this with explicit state + process control instead of end-to-end RL
  • Let's Verify Step by Step (Lightman et al., 2023) — process supervision outperforms outcome-only for complex reasoning; direct conceptual anchor for per-step evaluation
  • WebSailor — frames core capability gap as systematic uncertainty reduction, not raw retrieval volume
  • BrowseComp (OpenAI) — search quality scales with strategy, not access; evaluation must be benchmarked and difficult
  • SCoRe — reliable self-correction requires structured feedback, not naive prompting; supports recovery loop design
What we borrow vs what we don't claim
"This prototype approximates Search-R1's ideas with structured state and process-level control — without claiming full RL training."
  • Borrow: interleaved search and reasoning, step-level evaluation, diminishing-returns stopping
  • Don't claim: end-to-end trained PRM, RL policy updates, GRPO-trained orchestrator
  • The MVP shows the right structure — the training loop is the production gap
  • Generic agent stacks (LangGraph + parallel agents) are commodity — the PRM angle is the differentiator

Component: Guided Planner + Stopping Logic

Guided planner — decision priority (guided_plan)
Rule 1a  Sub-questions with no direct claims and not recently dead-ended
Rule 1b  Sub-questions with no direct claims (fallback if all recently dead-ended)
Rule 2   Challenge: search adversarially against HIGH-confidence groups (falsification)
Rule 3   Deepen: search sub-questions that already have evidence (corroboration)
Rule 4   Trigger DIMINISHING_RETURNS if recent steps are mostly REDUNDANT/DEAD_END and coverage ≥ 40%
Baseline ignores all rules — round-robin only.
Stopping policy — termination conditions
COVERAGE_MET
All sub-questions have at least 1 direct claim. Best outcome.
DIMINISHING_RETURNS
Last N steps mostly REDUNDANT or DEAD_END and min coverage ≥ 40%. Principled stop.
BUDGET_EXHAUSTED
Step limit hit before coverage or diminishing signal. Baseline default. Bad outcome.
Stopping quality metric = 1.0 if COVERAGE_MET or DIMINISHING_RETURNS, else 0.0.

Conflict Detection

How it works
  • Lightweight Jaccard gate before LLM call (0.08 same branch, 0.03 cross-kind)
  • Scope intersection check to avoid false cross-domain conflicts
  • LLM classifier: SUPPORT / CONTRADICT / UNRELATED
  • When contradiction found: both groups marked DISPUTED
  • Both get challenge_status = CHALLENGED_CONFLICT_FOUND
  • Provenance: each group records what challenged it
Why two-way matters
  • One-way marking leaves the older claim looking authoritative in the report
  • Both groups must be disputed — or the conflict isn't surfaced at all
Design philosophy
Surface "Source A says X, Source B says Y — no consensus" rather than LLM-resolving into a confident-sounding claim.
  • Research agents fail by being confidently wrong
  • Unresolved conflicts appear explicitly in the report
  • Connects to calibration: honest uncertainty beats plausible fabrication
CONFLICT_FOUND = one of the highest-value step outcomes (reward 0.7)

Recovery-Aware Research Loop

3-tier recovery escalation
  • Tier 1: Query variants (3x rewriter) — breadth before depth
  • Tier 2: Add empirical keywords, rewrite sub-question
  • Tier 3: Pivot to arxiv/openreview domain constraint
Signal tracking
  • _recent_sq_failure_streak(sq_id) — tracks consecutive dead-ends per sub-question
  • Threshold: 3 dead-ends → trigger escalation
  • StepRecord captures recovery_strategy and recovery_attempts
Additional search quality controls
  • Novelty enforcement: already-retrieved URLs blocked per step
  • Domain dedup: results from same domain de-weighted
  • Extractor rescue pivot: if extraction fails, retry with simplified prompt
  • Adjacent claim sink: low-domain-quality claims captured but not polluted into groups
Domain quality policy
  • Research domains (arxiv, openreview, acm): 0.9
  • .edu / .gov: 0.75    Default web: 0.5
  • Claims below threshold → adjacent (not counted against sub-question coverage)

Evaluation — Honesty, Not Plausibility

Principle 8: evaluate whether the system is honest relative to the evidence it collected — not whether the output sounds plausible. The evidence store is the ground truth.
Process + coverage metrics
  • Coverage completeness — fraction of sub-questions with direct claims
  • Search efficiency — NEW_EVIDENCE steps / total steps
  • Conflict surfacing rate — known-conflict queries that surface disputes
  • Stopping quality — COVERAGE_MET or DIMINISHING_RETURNS (Principle 7)
  • Summary grounding rate — report sentences traceable to store claims
Epistemic honesty metrics (Angle 2)
  • Unresolved disclosure rate — disputes in store appear in the report
  • Epistemic honesty score — hedged language for low-confidence claims
  • Uncertainty calibration — confidence labels match claim group strength
  • Unsupported summary rate — report claims with no store backing (target: 0%)
No human-labeled eval set yet — metrics are proxy measures validated by ablation delta, not ground truth. Validated eval harness is a production gap.

Production Path — Trained PRM

Bootstrap path (already feasible)
  • Run 100 sessions across diverse queries (partial: ablation_phase6)
  • LLM-as-judge labels each step: "Did this advance the research goal?" (0-3)
  • Training pairs: (state_before, action, state_after) → quality_label
  • Fine-tune Llama 8B + regression head, MSE loss
  • Validate: trained PRM rank agreement with judge on held-out set
Training data already captured
  • run_trace.json — step sequence + diagnostics
  • evidence_store.json — full before/after state per step
  • LLMCallRecord — every prompt + response, per component
GRPO connection
  • Policy: LLM generating search queries + challenge decisions
  • Reward: PRM score per step (process) + report quality (outcome)
  • Group: K research trajectories for same query, ranked by total PRM reward
  • Update: GRPO gradient on winning trajectories
Search-R1 applied to evidence-driven research instead of math reasoning. The key: rewarding good intermediate steps, not just fluent final output.

Honest Gaps

Known implementation gaps
  • Domain threshold misconfigured in phase2: 0.6 threshold sent most web claims to adjacent. Diagnostics made it immediately visible — fix is 3 lines. (Observability is the win.)
  • Summary grounding metric uses Jaccard — weak proxy for faithfulness. Production: LLM-as-judge on report sentences.
  • Stopping quality metric has a bug in this run — COVERAGE_MET termination is the correct signal; the metric will be patched.
  • Serial retrieval — query variants run sequentially. Production: asyncio.gather, 3x speedup.
Design gaps (not built)
  • ArXiv full-paper reader — tool defined, retriever not wired
  • Token budget tracking — calls traced, tokens not counted
  • Human feedback loop — no mechanism to correct a claim and re-trigger conflict detection
  • Multi-session memory — each run starts cold, no resume or merge
  • Trained PRM — design complete, training loop not started
  • Automated prompt regression tests — versioning exists, regression harness doesn't
